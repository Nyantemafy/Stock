==================================================
PROCESS - Résumé technique de l’aléa
==================================================

1. Résumé de l’aléa

L’aléa demandé concerne la saisie multiple des mouvements de stock.
L’objectif est de pouvoir saisir plusieurs entrées ou plusieurs sorties de stock, puis de valider toutes les lignes en une seule fois.

2. Modifications techniques principales

La saisie simple existante a été remplacée par une saisie multiple pour :
- l’entrée de stock ;
- la sortie de stock.

Chaque ligne de saisie correspond à un formulaire généré automatiquement avec le service existant FormGenerator.
L’utilisateur peut ajouter plusieurs lignes avec le bouton "Ajouter ligne" et retirer la dernière ligne avec le bouton "Supprimer ligne".

La validation reste unique :
- l’utilisateur remplit plusieurs lignes ;
- il clique une seule fois sur OK ;
- toutes les lignes valides sont enregistrées ensemble.

3. Changements dans les services généralisés

Le service généralisé FormGenerator a été enrichi pour gérer plusieurs formulaires du même type.

Méthodes ajoutées dans FormGenerator :
- genererFormulaires : crée un conteneur avec plusieurs formulaires.
- ajouterFormulaire : ajoute une nouvelle ligne de saisie.
- supprimerDernierFormulaire : supprime la dernière ligne.
- getFormulaires : récupère toutes les lignes saisies.
- estVide : permet d’ignorer une ligne totalement vide.

Le service AffichageGenerator a aussi été complété avec :
- genererScrollPane : permet d’afficher les lignes multiples dans une zone défilante.

Aucun service spécifique à l’aléa n’a été créé.
La logique reste donc basée sur les services généralisés existants du projet.

4. Changements dans l’interface

Dans Main.java, les actions "Entree stock" et "Sortie stock" utilisent maintenant des formulaires multiples.

Pour l’entrée de stock :
- la fenêtre affiche la fiche de l’article sélectionné ;
- les lignes saisies sont toutes enregistrées sur cet article ;
- les champs utilisés restent nombre, prixUnitaire, dateMouvement et idSource.

Pour la sortie de stock :
- la fenêtre affiche aussi la fiche de l’article sélectionné ;
- les lignes saisies sont toutes traitées comme des sorties de cet article ;
- les champs utilisés restent nombre et dateMouvement.

Les lignes complètement vides sont ignorées.
Une erreur est affichée si aucune ligne n’est saisie.
Une erreur est aussi affichée si une ligne est partiellement remplie ou contient une valeur invalide.

5. Changements dans le DAO

ArticleDao a été complété pour enregistrer plusieurs mouvements dans une seule transaction.

Méthodes ajoutées :
- ajouterMouvementsStock : enregistre plusieurs entrées de stock.
- ajouterSortiesStock : traite plusieurs sorties de stock.

Pour les entrées :
- chaque ligne est insérée dans mouvement_stock ;
- toutes les insertions sont faites dans une transaction.

Pour les sorties :
- chaque ligne réutilise la logique existante FIFO, LIFO ou CUMP ;
- la logique métier déjà présente n’a pas été remplacée ;
- elle a été déplacée dans une méthode privée réutilisable pour pouvoir traiter une ou plusieurs sorties.

Si une erreur arrive pendant le traitement d’un lot, la transaction est annulée.
Donc soit toutes les lignes sont enregistrées, soit aucune ne l’est.

6. Changements dans les modèles

MouvementStock a reçu un constructeur simplifié.

Ce constructeur permet de créer facilement un mouvement à enregistrer sans renseigner les champs calculés comme :
- idMouvementStock ;
- coutTotal ;
- coutUnitaireMoyenPondere.

Ces champs restent utilisés pour l’affichage des détails, mais ne sont pas nécessaires au moment de préparer une nouvelle ligne de saisie.

7. Fichiers modifiés ou créés

Fichiers modifiés :
- src/com/stock/generalisation/Main.java
- src/com/stock/generalisation/dao/ArticleDao.java
- src/com/stock/generalisation/model/MouvementStock.java
- src/com/stock/generalisation/service/FormGenerator.java
- src/com/stock/generalisation/service/AffichageGenerator.java

Fichier créé :
- process.txt

8. Résultat technique final

Le projet permet maintenant :
- de saisir plusieurs entrées de stock en une seule validation ;
- de saisir plusieurs sorties de stock en une seule validation ;
- de voir clairement l’article concerné dans la fenêtre de saisie ;
- de conserver la logique FIFO, LIFO et CUMP existante ;
- d’enregistrer les lots de mouvements avec une transaction.

Le champ idSource n’a pas été transformé en id produit.
Le produit concerné reste l’article sélectionné dans le tableau.
idSource garde son rôle de source du mouvement.
